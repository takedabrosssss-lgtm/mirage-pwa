MIRAGE v1.1.1 — ОБНОВЛЕНИЕ ДЛЯ СУЩЕСТВУЮЩЕГО РЕПОЗИТОРИЯ
=========================================================

Это OVERLAY-архив. Он не заменяет весь проект. Загружайте содержимое архива
в корень уже существующего репозитория mirage-pwa, сохраняя папки.

ЧТО БУДЕТ ЗАМЕНЕНО
------------------
- MIRAGE_V1.1_INSTALL.txt (эта инструкция обновляется)
- Procfile
- Dockerfile
- mirage_v11_fixes.py
- tests/test_v11_fixes.py

ЧТО БУДЕТ ДОБАВЛЕНО
-------------------
- app_v111.py
- .github/workflows/tests.yml

НЕ УДАЛЯТЬ И НЕ ЗАМЕНЯТЬ
-----------------------
Оставьте без изменений app.py, app_v11.py, market.py, trading.py, news.py,
requirements.txt, static/, data/ и остальные существующие файлы.

КАК ЗАГРУЗИТЬ
-------------
1. Откройте GitHub → takedabrosssss-lgtm/mirage-pwa → ветка main.
2. Нажмите Add file → Upload files.
3. Распакуйте ZIP на телефоне или компьютере.
4. Загрузите ИМЕННО СОДЕРЖИМОЕ распакованной папки, а не сам ZIP.
5. Сохраните структуру папок: .github/workflows/ и tests/ должны остаться
   папками с указанными файлами внутри.
6. Разрешите GitHub заменить 5 файлов из списка выше и добавить 2 новых.
7. Нажмите Commit changes в ветку main.

НАСТРОЙКА ХОСТИНГА
------------------
Procfile и Dockerfile теперь запускают app_v111:app. Если в настройках хостинга
задана собственная Start Command, замените её на:

uvicorn app_v111:app --host 0.0.0.0 --port $PORT --workers 1

Оставьте ровно один worker. Существующие переменные окружения и секреты
(DATABASE_URL, APP_SECRET, BOOTSTRAP_USERS_JSON, APP_ENV, регион) не удаляйте
и не перезаписывайте. Не вставляйте значения из .env.example вместо секретов.

ЧТО ИМЕННО ИСПРАВЛЕНО
---------------------
1. PHANTOM теперь является реальным запретом новых входов, а не только
   индикатором состояния. Проверка выполняется непосредственно перед
   открытием позиции, поэтому действует и для Auto Paper Trading, и для
   ручного открытия через API.
2. Новая сделка разрешается только при ACTIVE-состоянии PHANTOM, доступном и
   недавно проверенном Binance USDⓈ-M REST, а также при двух подключённых и
   свежих WebSocket-потоках: Mark Price и Bid/Ask.
3. REST fallback не считается достаточным основанием для нового входа.
   Он может продолжать помогать менеджеру обслуживать уже открытые позиции.
   Потеря WebSocket сама по себе не закрывает позицию и не меняет SL/TP.
4. Риск-расчёты, комиссии, Funding-обработка, логика стопов/тейк-профитов и
   существующие модули v1.1 не переписываются: app_v111 оборачивает
   существующий open_trade и проверяет PHANTOM до вызова торговой логики.
5. В /api/phantom появляется явная проверка New paper entries и поле
   new_entries_allowed. /api/health сообщает версию 1.1.1 и статус входного
   feed-gate.
6. Добавлены unit-тесты для защитного шлюза и GitHub Actions: тесты будут
   запускаться автоматически при push в main и при Pull Request.

ПРОВЕРКА ПОСЛЕ ЗАГРУЗКИ
-----------------------
1. Дождитесь завершения Deploy на хостинге.
2. Откройте /api/health: версия должна быть 1.1.1.
3. В /api/phantom проверьте поле state и пункт New paper entries.
4. Если любой из двух WebSocket-потоков отключён или устарел, PHANTOM должен
   быть PROTECTIVE, new_entries_allowed=false, а попытка открыть новую сделку
   должна быть отклонена.
5. В GitHub откройте Actions и проверьте workflow MIRAGE tests.
6. Не включайте Auto Paper Trading до подтверждения здоровых потоков и
   успешной проверки работы хостинга.

ВАЖНЫЕ ОГРАНИЧЕНИЯ
------------------
- Это Paper Trading. Архив не добавляет отправку реальных ордеров.
- Защитный шлюз блокирует новые позиции, но не может гарантировать исполнение
  SL/TP при полном отключении сервера или недоступности рыночных данных.
- Unit-тесты проверяют правила на тестовых данных, а не реальный доступ Binance
  из региона хостинга. REST и оба WebSocket endpoint всё равно нужно проверить
  после развертывания.
- Исторический Funding при длительном простое сервера не всегда может точно
  восстановить размер частично закрытой позиции на каждый прошлый момент
  начисления; это ограничение исторических данных текущей модели сделок.
